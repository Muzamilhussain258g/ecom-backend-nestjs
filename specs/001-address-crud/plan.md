## Summary

Implement customer shipping address book management (CRUD) allowing authenticated shoppers to create, list, retrieve, update, and delete their saved shipping addresses. The solution strictly enforces multi-tenant privacy isolation, a single-default address invariant per user across all lifecycle operations (via atomic Prisma interactive transactions), and preserves historical order shipping snapshots upon address deletion.

## Technical Context

**Language/Version**: TypeScript 5.7, Node.js 24 (Target ES2023)  
**Primary Dependencies**: NestJS 11 (`@nestjs/common`, `@nestjs/core`, `@nestjs/swagger`, `@nestjs/passport`), Prisma 7.8 (`@prisma/client`), `class-validator`, `class-transformer`, `passport`, `passport-jwt`  
**Storage**: PostgreSQL (Prisma ORM with existing `Address` model and `AddressType` enum)  
**Testing**: Jest 30 (`ts-jest`), Supertest  
**Target Platform**: Node.js Web Server / Docker  
**Project Type**: Web service / Modular REST API backend  
**Performance Goals**: < 100ms p95 latency for address CRUD operations  
**Constraints**: Strict tenant isolation by `userId`, atomic single-default guarantee using Prisma interactive transactions, safe API response mapping without exposing secrets or cross-user data, seamless integration with existing `TransformInterceptor` and `JwtAuthGuard`  
**Scale/Scope**: 1 new NestJS feature module (`AddressModule`), 1 controller, 1 service, 3 DTOs, unit and controller tests, OpenAPI Swagger decorators
